# Secure Excel Transfer VBA

이 도구는 DRM/DLP 또는 클립보드 차단을 해제하거나 우회하지 않습니다. 보안팀이 미리 승인한 폴더의 `.xlsx` 또는 `.csv`를, 정확히 승인된 `.xlsm` 통합문서의 빈 범위로 **값만** 가져옵니다. 접근·읽기·저장이 차단되거나 권한 상태를 확인할 수 없으면 작업을 중단하며 다른 방법으로 재시도하지 않습니다.

## 제공 파일

- `SecureTransfer.bas`: 일반 사용자가 실행할 가져오기 모듈
- `SecureTransferAdminSetup.bas`: IT/보안 관리자가 배포 준비 중 한 번만 사용하는 초기화 모듈. 배포 전에 반드시 제거
- `ThisWorkbook_Code.txt`: 대상 통합문서의 `ThisWorkbook` 코드 영역에 붙일 시작 검증 이벤트
- `QUICK_START.md`: 일반 사용자를 위한 한 페이지 사용법
- `SECURITY_REVIEW_CHECKLIST.md`: 보안팀 검토 및 승인 체크리스트

## 동작 범위

- 원본: 관리자 설정의 `AllowedRoot` 아래에 있는 `.xlsx` 또는 `.csv` 한 개
- 대상: 설정에 전체 경로가 고정된 현재 `.xlsm` 파일
- 기록 방식: 원본 수식 자체가 아닌 현재 값만 기록
- 대상 범위: 표시 상태이고 보호되지 않았으며 완전히 비어 있는 일반 셀 범위
- 감사 로그: 원본 파일명, 대상 파일명, 처리 시각, 가져온 행 수만 기록
- 저장: 값 기록과 감사 로그 기록이 모두 성공한 경우 대상 통합문서를 즉시 저장

다음 동작은 포함하지 않습니다.

- 클립보드 읽기·쓰기 또는 붙여넣기 재시도
- `SendKeys`, 키 입력 자동화, 마우스 자동화
- 프로세스 조작, DLL 후킹, 화면 캡처 또는 OCR
- DRM/DLP 서비스 중지, 설정 변경 또는 API 우회
- 차단된 파일을 다른 형식·임시 파일·별도 프로세스로 재추출
- 외부 데이터 연결이 포함된 `.xlsx` 가져오기

## 사전 조건

1. 보안팀이 원본 분류, 대상 분류, 업무 목적, 승인 루트, 정확한 대상 파일을 승인해야 합니다.
2. 보안팀은 Excel 개체 모델을 통한 이 값 가져오기가 NSD 정책에서 허용되는 업무 흐름인지 확인해야 합니다.
3. 대상 파일과 승인 루트에는 조직의 NTFS/SMB 접근제어를 적용해야 합니다.
4. Windows 데스크톱 Excel과 조직에서 허용한 VBA 실행 정책이 필요합니다.
5. CSV는 임시 파일 없이 메모리에서 읽으며 Windows의 `ADODB.Stream`을 사용합니다.

## 관리자 설치

설치는 운영 파일이 아닌 새 배포 사본에서 IT/보안 관리자가 수행합니다.

1. 대상 통합문서를 보안팀이 승인한 폴더에 `.xlsm` 형식으로 저장합니다.
2. `Alt+F11`을 눌러 VBA 편집기를 엽니다.
3. `파일 > 파일 가져오기`에서 `SecureTransfer.bas`와 `SecureTransferAdminSetup.bas`를 가져옵니다.
4. 프로젝트 탐색기의 `Microsoft Excel Objects > ThisWorkbook`을 열고 `ThisWorkbook_Code.txt` 내용을 붙여 넣습니다.
5. `SecureTransfer_AdminInitialize` 매크로를 실행합니다.
6. 승인 루트, 승인자/티켓, 승인 만료일, 구조 보호 암호를 입력합니다. 처리 한도와 CSV 인코딩은 `아니요`를 선택하면 권장 기본값을 사용합니다.
7. 완료 메시지가 나타나면 `SecureTransferAdminSetup` 모듈을 프로젝트에서 제거합니다. 운영 파일에 이 모듈을 남기지 마십시오.
8. VBA 편집기의 `디버그 > VBAProject 컴파일`을 실행하고 컴파일 오류가 없는지 확인합니다.
9. 조직 코드서명 인증서로 VBA 프로젝트를 서명하고 저장합니다.
10. 조직 정책에서 신뢰된 게시자의 서명된 매크로만 실행되도록 설정합니다. 광범위한 `신뢰할 수 있는 위치` 사용은 피합니다.
11. 파일을 닫았다가 다시 열어 `Secure Transfer` 시작 화면과 세 개의 버튼이 나타나는지 확인합니다. 필요하면 VBA 편집기의 직접 실행 창에서 `? SecureTransfer_IsReady(True)`도 실행합니다.
12. 보안팀 테스트가 끝난 서명본만 사용자에게 배포합니다.

VBA 편집기에서 한글이 깨지면 Windows 메모장에서 `.bas` 파일을 열어 시스템 기본 ANSI(한국어 Windows에서는 일반적으로 CP949)로 다시 저장한 뒤 가져오십시오. 코드를 변경한 뒤에는 반드시 다시 검토하고 서명해야 합니다.

이전 버전으로 이미 봉인한 파일은 코드를 직접 덮어쓰지 마십시오. 시작 화면 생성과 코드서명 갱신이 필요하므로 IT/보안 관리자가 새 배포 사본에서 위 초기화 절차를 다시 수행해야 합니다.

### 설정값

| 설정 | 의미 |
|---|---|
| `SchemaVersion` | 설정 구조 버전 |
| `DeploymentState` | `SEALED`인 경우만 실행 |
| `ApprovalStatus` | `APPROVED`인 경우만 실행 |
| `AllowedRoot` | 원본과 대상이 위치해야 하는 승인 루트 |
| `ApprovedWorkbookFullName` | 승인된 대상 `.xlsm`의 정확한 전체 경로 |
| `ApprovedBy` | 승인자 또는 승인 티켓 식별자 |
| `ApprovalExpiry` | `yyyy-mm-dd` 형식의 승인 만료일 |
| `MaxRows` | 한 번에 허용할 최대 행 수 |
| `MaxColumns` | 한 번에 허용할 최대 열 수 |
| `MaxCells` | 한 번에 허용할 최대 전체 셀 수 |
| `MaxFileMB` | 허용할 최대 원본 파일 크기 |
| `CsvCharset` | `utf-8`, `ks_c_5601-1987`, `windows-1252` 중 하나 |
| `ConfigChecksum` | 우발적인 설정 변경을 감지하는 CRC32 검사값 |

## 사용자 사용법

1. 승인된 대상 `.xlsm`을 엽니다.
2. 파일에 다른 미저장 변경 사항이 없는지 확인합니다. 있으면 먼저 저장합니다.
3. 자동으로 열리는 `Secure Transfer` 화면에서 큰 **파일 선택하고 가져오기** 버튼을 누릅니다.
4. 승인 폴더 안의 `.xlsx` 또는 `.csv`를 고릅니다.
5. `.xlsx`라면 가져올 범위를 마우스로 드래그하고 **확인**을 누릅니다. CSV는 이 단계가 생략됩니다.
6. 대상 문서에서 비어 있는 시작 셀 하나를 클릭하고 **확인**을 누릅니다.
7. 완료 메시지를 확인합니다. 가져온 위치로 화면이 이동하고 문서와 감사 로그가 자동 저장됩니다.

시트명이나 `A1:H200` 같은 범위 주소를 직접 입력할 필요가 없습니다. 시작 화면의 **빠른 사용법**과 **승인 상태 확인** 버튼도 사용할 수 있습니다.

CSV는 설정된 문자 인코딩으로 전체 파일을 읽습니다. CSV의 모든 값은 외부 프로세스나 임시 파일 없이 메모리에서 처리됩니다.

한 페이지만 보고 사용하려면 [`QUICK_START.md`](QUICK_START.md)를 참고하십시오.

## 차단·오류 시 동작

- 파일 열기, 값 읽기 또는 대상 저장이 거부되면 즉시 중단합니다.
- Microsoft 권한 관리가 감지되거나 상태 확인이 실패하면 중단합니다.
- 문자열이 Excel 수식으로 만들어진 흔적이 있으면 작성한 범위를 지우고 중단합니다.
- 감사 로그 기록이나 저장이 실패하면 작성한 값과 미완성 로그를 되돌립니다.
- DRM/DLP 차단을 다른 입력 수단으로 우회하여 재시도하지 않습니다.

NSD가 표시하는 “사업장 정책에 따라 붙여넣기를 허용하지 않습니다” 메시지를 이 VBA가 직접 감지하거나 해제할 수는 없습니다. 그 메시지가 나타나는 파일 조합은 보안팀의 정책 변경 또는 명시적 예외 승인 전까지 사용하지 마십시오.

## 중요한 보안 한계

- Excel 시트 보호, 구조 보호, VBA 프로젝트 잠금은 강한 보안 경계가 아닙니다. 실제 통제는 조직 코드서명, 서명 강제 정책, 폴더 ACL, 승인된 배포 과정이 담당해야 합니다.
- `ConfigChecksum`은 우발적인 변경 감지용이며 악의적인 변조를 암호학적으로 방지하지 않습니다.
- 서드파티 DRM의 적용 여부를 VBA가 신뢰성 있게 판별할 수 없습니다. 따라서 보안팀이 승인 루트와 파일 조합을 직접 검증해야 합니다.
- 단순 경로 검사는 재분석 지점·심볼릭 링크의 최종 대상을 보증하지 않습니다. 승인 루트에서 해당 기능을 제한하고 파일 서버 ACL로 보완해야 합니다.
- 값만 가져오므로 원본의 서식, 주석, 도형, 연결, 매크로, 수식은 복사하지 않습니다.

운영 승인 전에는 `SECURITY_REVIEW_CHECKLIST.md`의 모든 필수 항목을 검토하십시오.
